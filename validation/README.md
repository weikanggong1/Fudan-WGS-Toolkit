### 默认多 CPU 准备

多染色体使用 `spawn` 进程，单染色体使用多线程 BED 解码；`cpu_threads=8` 是总预算，`cpu_threads=1` 为串行。接口检查实际执行了两个匿名染色体的独立进程，验证请求顺序、每个子进程的预算、整体完成标记、检查点恢复及失败时阻止基因型写入；它是接口测试，不是多染色体真实速度 benchmark。

真实转换对照使用相同的 341,101 人、1,536 SNV 和 6 帧，重新读取原始 PLINK 与独立官方注释，各写入全新目录。

| CPU 解码线程 | 准备总时间 | 注释预检 | BED 转换与元数据 |
| --- | --- | --- | --- |
| 1 | 116.95 秒 | 85.34 秒 | 22.87 秒 |
| 8（默认） | 96.08 秒 | 72.94 秒 | 15.08 秒 |

两份新输出与既有准备数据的基因型状态、整数计数、FID/IID 顺序及注释字段完全一致。测量顺序为先 1 后 8，原始文件的页面缓存已热；注释预检的差异不能归因于解码线程数量。这不是完整染色体的转换时间，也不是冷启动速度保证。两轮共享进程的累计峰 RSS 为 1,339.22 MiB，不能当作各轮独立峰值。计时之后增加了恢复和临时轴文件的完整性检查，编码与数值路径保持相同；这些新增检查由最终回归覆盖。

### 模型与精度口径

新公共入口拟合无亲缘结构的普通模型；本次使用 12 个连续表型和 1 个显式二分类表型，保持原始已处理表型数值，不额外 RINT。每个表型独立使用其完整案例及相应协变量设计。与历史混合模型的结果不能直接当成数值对照。

同输入 Python FP64 控制复用本次保存的零模型、FID/IID、REF 方向、注释、mask 和缺失处理；只改变关联计算精度。显著并集定义为任一实现 P<0.05，目标最大 `|Δ−log10(P)|≤0.001`。CSV 行顺序、样本数、位点集合及 mask 计数另行检查。没有记录可恢复 logP 的真正零 P 不做任意截断；它不能被算作通过精度检查。

最终冻结版本的独立对照已完成。逐个表型的 TF32 运行与共享运行的 52 个 CSV 逐字节一致，有限数值逐位相同，NaN/Inf 位置一致；对照复用相同已拟合零模型，不重新拟合。CPU FP64 对照的列、行身份、顺序及缺失位置也全部一致。

| 与同模型 CPU FP64 对照 | P<0.05 显著并集单元数 | 最大 Δ−log10(P) |
| --- | --- | --- |
| Single | 25 | 0.00000230 |
| coding | 622 | 0.00049628 |
| noncoding | 228 | 0.00002311 |
| ncRNA | 162 | 0.00003641 |
| 全部 | 1,037 | 0.00049628；99 分位数 0.00048488 |

全部显著并集单元达到 0.001 目标。16,775 个有限 P 值的全范围诊断最大误差为 0.00330118，不能据此宣称所有 P 值达到 0.001。另有 348 个双方一致的缺失概率单元，未作为零 P 纳入比较；无无效、零值或无法恢复对数的概率。Single 的 537 个已保存对数概率均为有限值。

| 关联阶段（复用本次同一零模型） | 内部运行时间 | 进程总时间 |
| --- | --- | --- |
| 共享 13 表型 TF32 | 77.75 秒 | 包含在上面的 397.03 秒端到端中 |

这些控制依次运行，未同时占用 GPU。表中没有重新拟合零模型，因此不能与包含拟合的端到端时间直接作比。共享与独立运行的区别同时包含读取、传输、缓存及计算组织，不把整体时间差单独归因于矩阵精度。这是同模型 Python 精度控制，不是本版与原软件的完整端到端等价证明；本轮也未验证大 mask 的随机谱。

### 覆盖边界

独立官方库首批 65,536 个原始位点中，57,905 个有精确对应，7,631 个非 SNV 没有注释；SNV 缺失为 0。默认严格转换已阻止这个不完整的全变异输入。未使用其他版本或历史缓存填补未知注释。显式保留无注释非 SNV 的策略见使用说明；它不提供这些位点的 gene-based 权重。

真实局部准备不等于整条染色体转换完成；原始源文件有 13,733,596 个变异，当前核对过的基因型状态范围见上表。
